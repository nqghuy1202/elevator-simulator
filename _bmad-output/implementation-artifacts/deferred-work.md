- source_spec: `_bmad-output/implementation-artifacts/spec-1-3-pending-call-re-evaluation.md`
  summary: An idle elevator sitting exactly at a floor with two opposite-direction pending Hall Calls for that same floor can be selected twice in one `reevaluatePending()` pass, causing one harmless-but-unnecessary extra door-open/dwell cycle before settling Idle.
  evidence: Root cause is in Story 1.1's `IdleState`/`DoorOpenState` same-floor immediate-open fix, which never updates `direction` away from `'IDLE'` — so the elevator stays `IDLE`-eligible (any direction) for a second pending call at the same floor. Traced end-to-end: functionally harmless (the floor is still served correctly, no call is lost or mis-served), but an observable inefficiency. Reachability requires a narrow, compound trigger (two opposite-direction pending calls at the exact floor an idle elevator already occupies) not exercised by Story 1.3's own scope. Flagged for Story 1.4 (Stop Queue Integrity), which already owns related same-floor/queue invariants.
